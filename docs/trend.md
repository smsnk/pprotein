# 収集をまたいだ推移

pprotein の UI は1回の収集のスナップショット表示が中心で、**走行をまたいだ比較**ができなかった。
素振りでは「施策を入れる → ベンチ → 結果を見る」を何十回も繰り返すので、
「前回と比べてどのエンドポイントが改善したか / 悪化したか」の突き合わせが毎ラウンドの固定コストになる。

`trend` タブは、収集を横軸に取ったグラフを1画面にまとめる。

## 見えるもの

| グラフ | 指標 |
| --- | --- |
| score | ベンチのスコア（`score` の収集が要る） |
| httplog | 合計レスポンスタイム / リクエスト総数 |
| slowlog | 合計クエリ時間 / 走査行数の合計 |
| エンドポイント別 | 選んだエンドポイントの SUM と AVG |

- **各点の x 軸ラベルはコミットの短縮ハッシュ。** どの施策の点かがグラフ上で分かる
  （git 情報が無い収集は時刻を出す）
- グラフにカーソルを合わせると、**全グラフの同じ収集**に縦線が入り、
  上の帯にその収集の GroupId・時刻・スコア・コミットメッセージが出る
- 一番下に**直近2回のエンドポイント単位の差分**が出る。増減の大きい順で、改善は青・悪化は赤

## API

グラフのデータは `GET /api/trend` で取れる。CLI やスクリプトからも使える。

```sh
curl 'http://localhost:9000/api/trend?limit=20&top=8'
```

| クエリ | 既定 | 内容 |
| --- | --- | --- |
| `limit` | 20 | 遡る収集の数（最大 100） |
| `top` | 8 | 各収集で明細に載せるエンドポイント / クエリの件数 |

返り値の `Groups` は**古い順**（グラフの左から右）。

```json
{
  "Groups": [
    {
      "ID": "2025-11-23_10-41-02.984213",
      "Datetime": "2025-11-23 10:41:02",
      "Commit": { "Hash": "a1b2c3d...", "Message": "notification をキャッシュする", "Ref": "refs/heads/12-cache" },
      "Score": { "Value": 18902, "Passed": true },
      "Metrics": {
        "score": 18902,
        "httplog.sum": 62.31, "httplog.count": 4200,
        "slowlog.sum": 12.4, "slowlog.count": 880, "slowlog.rows_examined": 1020100
      },
      "Endpoints": [{ "Label": "isu1", "Key": "GET /api/app/notification", "Count": 4200, "Sum": 62.31, "Avg": 0.0148 }],
      "Queries":   [{ "Label": "isu1", "Key": "SELECT ...", "Count": 880, "Sum": 12.4, "Avg": 0.014 }]
    }
  ]
}
```

## 実装メモ

- 集計は `internal/summary`（`pprotein-cli` と同じ経路）を使っている。
  自分自身の API 経由で読むので、alp / pt-query-digest の処理結果は**サーバー側のキャッシュがそのまま効く**
- グラフは依存を増やさないよう素の SVG で描いている
- 収集中 / 壊れている group は飛ばす
- 過去分をどこまで残すかは pprotein のデータディレクトリ次第。
  回をまたいで残すと `limit` の範囲に別の回の収集が混ざるので、回ごとにデータを分けるか
  `limit` を小さくして使う
